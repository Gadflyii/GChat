# Model Context Protocol in GChat

GChat can discover and call tools from configured Model Context Protocol (MCP)
servers. Those tools use the same approval and cancellation controls as other
Chat and Agent tools.

The Linux client scope covers trusted local servers over **STDIO** and remote
servers over **Streamable HTTP** or **SSE**, with static credentials supplied in
environment variables or HTTP headers. OAuth sign-in and token refresh are not
supported.

See [MCP Servers](/docs/desktop/integrations/mcp-servers) for configuration,
permissions and troubleshooting.

## Trust and access

Enable servers you trust. A local STDIO server runs as your operating-system
user and can access the files, environment and network available to that
process. A working directory or a GChat workspace selection does not sandbox
external server code. The server must enforce any access restrictions it offers.

A remote server receives the arguments sent to its tools. Review the server's
identity and each requested action before approval, especially when arguments
contain private data. Approving a tool action does not make the server's code
or returned content trustworthy.

Server configuration, including environment variables and HTTP headers, is
saved locally in GChat's data folder. It is not an encrypted credential store.
Keep credentials out of exported configuration, screenshots and shared logs.

## Tool execution

With **Manually approve** selected, the shared approval dialog offers **Deny**
or **Approve once**. Where available, **Always allow this action** remembers the
specific tool and arguments across restarts. **Skip all approvals** permits
actions without that prompt; choose it only for a workflow whose tools and
inputs you trust.

**Stop** cancels GChat's pending execution. A server may already have performed
an action, so cancellation does not undo external changes.

This integration exposes MCP tools to GChat. It does not qualify every server,
or add MCP resource and prompt browsing. Inference-server hosted MCP tools are
a separate unsupported request type and return an explicit error.
