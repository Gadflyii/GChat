# File Upload

GChat can attach local documents to a conversation and read them with its native file tools. This is direct file access: attaching a document does not create a searchable vector index. Embedding-based RAG and project-document indexing are unavailable until GInfer provides embeddings.

## Add documents

1. Select a model that supports tools.
2. Click **+** in the chat input and choose **Add documents or files**, or drag files into the conversation.
3. Select the documents and ask your question.
4. In **Available Tools**, keep the native document reader enabled if you want the model to read files as needed.

With **Auto** document handling and native reading enabled, GChat keeps the file's local path as a reference. It does not parse or index the file before sending the message. The model can request its contents through `os_fs_read_document` in the `gchat-native` tool group. A saved reference still points to the original file, so moving or deleting that file can prevent a later read.

If native reading is disabled, unavailable, or unsupported by the selected model, Auto can extract a selected attachment's text inline instead. Explicit inline handling also extracts the text before sending. **Disabling the native tool blocks its invocation; it does not block inline extraction of a file you select.** Explicit embedding-based handling does not fall back to native reading and is unavailable with the current GInfer backend.

## Read and search local files

The native tools provide different ways to inspect documents:

- `os_fs_read_document` extracts text from a document at a local path.
- `os_fs_glob` finds paths by filename pattern within a directory.
- `os_fs_grep` searches text files with a regular expression. It follows ignore rules, does not follow directory symlinks, and skips individual files that are unreadable, non-text, or larger than 1 MiB during recursive searches. Searching such a file directly returns an error. It does not search the extracted contents of PDFs, Word documents, or spreadsheets; read those documents first.

These tools use the conversation or Agent workspace and its folder permissions. Attaching a file does not automatically grant access to its parent directory. A request outside the allowed folders can show a folder-access dialog: **Deny** rejects the request, while **Allow** adds the displayed folder with **CAN EDIT** access. Reads already permitted by the workspace policy do not necessarily show a separate approval dialog.

**Available Tools** lets you disable individual tools. When an approval dialog is required, it shows the requested operation and arguments so you can approve or deny it. **Stop generation** can cancel a request waiting for permission. In-progress document parsing does not currently observe cancellation immediately.

## Supported document formats

The document parser supports:

- Text-based **PDF**. Scanned or image-only PDFs with no extractable text require OCR, which is not supported.
- **DOCX** Word documents and **PPTX** PowerPoint presentations.
- **XLSX**, **XLS**, and **ODS** spreadsheets, with sheet names and cell values extracted as text, plus **CSV** files.
- **HTML**, plain text, Markdown, and supported source-code or configuration files.

Extraction returns plain text. Native document reads limit extracted text to 16,000 characters by default; a request can set `maxChars` up to 50,000. A shortened result includes a truncation marker. File searches also have bounded output, so refine the path or pattern when a result is truncated. A missing, unreadable, or unparseable file returns an error. These are output limits: the parser still reads the complete document before truncating its text.

## Images and privacy

Use **Add Images** with a model that supports vision for screenshots or pictures. Document text extraction does not perform image recognition or OCR.

File parsing and native file searches run locally. Extracted text and tool results can become part of the conversation sent to the selected model provider. Check the selected provider before sharing sensitive documents.
